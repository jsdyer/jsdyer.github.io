How CoolCode works

I’m Jeffrey Dyer, an independent Canadian developer. CoolCode grew out of questions about places I know in British Columbia and Nova Scotia. Which Halifax ferry can I catch? How far ahead do people book a campsite? You should be able to get an answer, see where it came from and get on with your day.

What you can count on

This is my commitment against enshittification. A tool that’s useful to you today should stay useful as the site grows.

  • Keep public tools free and open. Existing free features stay free to use without a CoolCode account.
  • Keep money out of results. No ads, sponsored rankings or paid spots in the directories.
  • Respect what you enter. Local calculators and private shortlists work on your device. For a live lookup, explain which service gets the request and what it needs. Searches, uploaded files and private notes stay out of our usage statistics.
  • Make figures checkable. Link published numbers to the original data, identify the period and geography, and label estimates and assumptions. For calculators, show the units and explain the arithmetic.
  • Respect your time and connection. Start with the task, keep pages light, and keep guides readable without JavaScript. Leave out signup popups, autoplay and advertising scripts.

If a tool falls short of a commitment, tell me which tool and what happened.

Where the figures come from

The dataset directory explains what each tool measures. Look for source coverage, the date the underlying figures describe, and the last time CoolCode checked them. A fresh check can still return the same edition. You can also read worked examples or inspect the catalogue source.

What the site counts

CoolCode counts tool opens and interactions with featured homepage cards. The counter gets a tool name, event type and, for a homepage experiment, a lineup. It receives no search terms, file contents, full page addresses or visitor accounts. The homepage can keep a lineup assignment for the current tab.

The counter runs on CoolCode’s Cloudflare service. It uses temporary, salted network-address values for rate limiting. Global Privacy Control and Do Not Track disable these browser statistics where the browser provides either signal. We do not sell visitor data or use third-party advertising trackers.

Opening a map, running a live lookup or following an external link can connect your browser to another service. Its operator receives the request and standard connection details. Check the source or privacy note on the tool for its specific behaviour.

Optional browser diagnostics

If you’re helping troubleshoot, you can enable error reports for this tab. On supported tools, a report sends Sentry the tool name, a standard error category and a location in CoolCode’s published script. Sentry receives standard network information when your browser connects. Reports omit error messages, search terms and file contents. Global Privacy Control and Do Not Track take precedence.

To report something directly, use the problem report form. Include what you expected and leave out sensitive information.
