How to check SPF, DKIM and DMARC for an email

25 November 2026

A message arrives with your organization's name in the From field. To understand the authentication evidence, you need two things: the original headers and the names that were actually checked.

Start with the message

In your mail app, view the original message or source. Open the email header analyzer and paste the headers locally. Find the Authentication-Results field added by your receiving mail system. Messages may contain additional copies farther down the chain, including claims inserted before the message arrived.

Look up the right names

  1. For SPF, note the envelope sender domain from the receiver's result. It can differ from the address shown in the From line.
  2. For DKIM, find the d= signing domain and s= selector in a DKIM-Signature header. For an illustrative pair of d=example.org and s=mail, the name to look up is mail._domainkey.example.org. Substitute the values from your own message.
  3. Open the DNS record checker to inspect the published records. Check DMARC for the domain used in the visible From address. Record which domain each passing mechanism authenticated and whether it aligns with From.

Explain a mismatch

A domain can publish a DKIM key today even when yesterday's message failed verification. The selector could have changed, or the message could have changed in transit. DNS Lens shows the records its resolvers return at lookup time. The receiver's headers describe its decision when the message arrived. Keep both timestamps when diagnosing a failure.

A passing authentication result also leaves the content of a message to evaluate. For a request to change banking details, contact the organization through a contact method you already use.

Technical references: DKIM signatures and Authentication-Results headers.
